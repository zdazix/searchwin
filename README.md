# SearchWin.ai: сайт агентства органического роста в эпоху AI-поиска

Сайт агентства органического роста с фокусом на AI-поиск. Страницы сделаны в формате визуального сторителлинга: каждая рассказывает одну историю о том, как клиент проходит путь от вопроса в ChatGPT до покупки, записи или подписанного договора.

**Сквозной посыл:** мы не просто делаем бизнес видимым в ИИ, а приводим оттуда звонки, записи, лиды, продажи и клиентов. Главная обращается к любому бизнесу, а для SaaS и B2B есть отдельные страницы со своими примерами, цифрами и метриками.

## Страницы

| Адрес | Файл | Для кого | Что считаем результатом |
|---|---|---|---|
| `/` | `index.html` | Любой бизнес: e-commerce, клиники, локальный бизнес, юристы, финансы, недвижимость и туризм, плюс плитки SaaS и B2B со ссылками | Звонки, записи, лиды, заказы, выручка |
| `/saas/` | `saas/index.html` | SaaS: sales/martech, HR tech, fintech, кибербезопасность, dev tools, аналитика, вертикальный SaaS, PLG | Триалы, демо, SQL, пайплайн, MRR |
| `/b2b/` | `b2b/index.html` | B2B вне SaaS: производство, логистика, промышленность, IT-услуги, профуслуги, стройка, опт, энергетика | RFQ, звонки отдела продаж, предложения, контракты |

Все три страницы собраны на одной структуре и одних стилях/скриптах (`assets/`). Отличаются тексты, облако запросов, примеры в инфографике, статистика, кейсы, отрасли, FAQ и сценарии анимации в hero. Подстраницы ссылаются на ресурсы через `../assets/`.

## Как посмотреть

```bash
python3 -m http.server 8080
# открыть http://localhost:8080
```

Можно просто открыть `index.html` двойным кликом, но Chrome не грузит шрифты с `file://`, поэтому для честного просмотра лучше локальный сервер.

Режим **`?ph`** или **`#ph`** (`http://localhost:8080/?ph`) подсвечивает оранжевой рамкой все места, где стоит временный текст или цифры, которые нужно заменить.

## Дизайн (версия 2, по референсу scrunch.com)

- **Типографика как у HubSpot:** у HubSpot заголовки набраны антиквой HubSpot Serif, а текст гротеском HubSpot Sans. Оба шрифта фирменные и закрыты лицензией, поэтому взяты ближайшие свободные аналоги: заголовки **Source Serif 4** (Medium), текст, кнопки, подписи и логотип **Lexend** (прежний фирменный шрифт HubSpot, из той же линии). Подписи источника в карточках (например, «ChatGPT / Prompt») набраны моноширинным IBM Plex Mono. Шрифты лежат в `assets/fonts/`.
- **Логотип:** только надпись `searchwin.ai` шрифтом Lexend, без значка, `.ai` того же чёрного цвета. Favicon: буква S.
- **Кнопки плоские:** без обводки и без тени снизу.
- **Палитра земли:** кремовый фон, бежевые секции, тёмно-коричневые секции для фактов и цифр. Наш собственный акцент: лаймовый. Он отмечает только то, что приносит деньги: кнопку отчёта, ваш бренд в ответах ИИ, демо и выручку.
- **Инфографика в стиле продуктового дашборда:** тёмные карточки с вопросом покупателя и подписью источника, светлые карточки с кольцевыми диаграммами, лаймовые полоски-«таблетки», графики с синей заливкой, полупрозрачные матовые подложки за карточками и курсор. Всё это лежит на размытых цветных фонах с зерном (небо, оливковый луг, закат, лагуна, персик, тёмный для тёмных секций). Фоны сгенерированы скриптом `tools/gen-backgrounds.py`, поэтому лицензионных вопросов по ним нет.
- **Пунктирные линии** разделяют секции, цифры и строки таблиц.
- **Убрано всё шаблонное из версии 1:** плавающий «док» с этапами, мосты-линии между главами, курсивные акцентные слова, пилюли с точками, мигающие индикаторы «live», галочки в кружках, побуквенные анимации заголовков.
- **Цвет в графиках несёт смысл:** синий означает видимость (упоминания, доля голоса), зелёный означает выручку (демо, пайплайн, сделки). Пары цветов проверены на различимость при дальтонизме.

## Форма заявки

По умолчанию форма открывает почтовый клиент посетителя с готовым письмом на `hi@searchwin.ai`, поэтому заявка не теряется молча. Чтобы заявки приходили автоматически, добавьте эндпоинт в `<form>`:

```html
<form class="form card" data-form data-endpoint="https://formspree.io/f/XXXXXXX" novalidate>
```

Скрипт отправит `POST` с JSON `{ name, email, website, prompt }`. Подойдёт Formspree, Make/Zapier webhook, HubSpot через прокси или свой API.

## Где что редактировать

- **Тексты:** `index.html`, `saas/index.html`, `b2b/index.html`, каждая секция подписана комментарием. Общий блок (шапка, футер, методология) правится в каждом файле.
- **Сценарии анимации в hero** (ассистент, вопрос, страница сайта, событие, сумма) и подписи в блоке со 100 точками: JSON в `<script type="application/json" id="page-config">` внизу каждой страницы. Если блока нет, берутся SaaS-сценарии по умолчанию из `assets/js/main.js`.
- **Запросы в облаке:** `index.html`, секция `#prompt`. Класс `q--hot` выделяет запрос тёмным.
- **Практики методологии:** текст в списке `.method__list`, карточка и фон для каждой практики в `.vpanel` с тем же номером (`data-mrow="2"` ↔ `data-vpanel="2"`).
- **Цвета, шрифты, отступы:** `:root` в `assets/css/styles.css`.
- **Фоновые картинки:** `assets/img/bg/`. Пересоздать: `python3 tools/gen-backgrounds.py assets/img/bg` (нужны numpy и Pillow).
- **Иконки:** SVG-спрайт в начале `<body>` (`#i-openai`, `#i-gemini` и т. д.).

## AI- и SEO-готовность

Сайт агентства по AI-поиску сам должен хорошо читаться ИИ:

- семантическая разметка, один `h1` на страницу, свой canonical, title и description у каждой страницы, JSON-LD (`Organization`, `ProfessionalService` с услугами из методологии, `WebPage`, `FAQPage` со своими вопросами);
- `llms.txt` с кратким описанием агентства и методологии для языковых моделей;
- `robots.txt` явно открывает доступ GPTBot, OAI-SearchBot, PerplexityBot, ClaudeBot, Google-Extended и другим;
- `sitemap.xml` со всеми тремя страницами, Open Graph-картинка `assets/img/og.png`, favicon;
- шрифты на своём хостинге, без сторонних запросов.

## Доступность и производительность

- `prefers-reduced-motion`: анимации и плавный скролл отключаются, облако запросов становится статичным, экран методологии переключается без анимации.
- Без JavaScript весь контент виден.
- Видимый фокус с клавиатуры, ссылка «Skip to content», у графиков есть текстовые описания и подсказки при наведении и фокусе.
- Адаптив проверен на 1440 и 390 px. На телефоне текст сторителлинга идёт карточками поверх «прилипшей» инфографики.
- Фоновые картинки в WebP, 20–160 КБ каждая, ниже первого экрана грузятся лениво.

## Бесплатная проверка «Does ChatGPT Recommend You?» (`/ai-check`)

ТЗ: [`docs/ai-check-spec.md`](docs/ai-check-spec.md). Этап 1 в упрощённом виде: страница, реальные ответы ChatGPT через DataForSEO, распознавание бизнеса, заявка на полный аудит, браузерные события Meta и Google. Писем сайт не отправляет: заявка сохраняется в таблицу `leads` и приходит уведомлением в Telegram.

### Как это устроено

Без очередей и фоновых задач: проверку ведёт сама страница.

```
Браузер /ai-check
  1. POST /api/ai-check/parse   Turnstile → чтение сайта (главная, затем /contact или /about,
                                защита от SSRF) → Gemini: название, услуга, город, регион, страна, язык
                                ← три вопроса + подписанный билет на 5 минут (в билете вопросы, страна, язык)
  2. 3 × POST /api/ai-check/ask  параллельно, по одному на вопрос; каждый ждёт ответ DataForSEO Live
                                (~45–60 с) и возвращает уже разобранный ответ
     страница показывает ответы по мере прихода и сама считает итог (assets/js/ai-check-core.js)
  3. POST /api/ai-check/audit   Turnstile → проверка email → строка в leads → Telegram
```

- У каждого маршрута лимит 150 с (`vercel.json`). DataForSEO ждём не дольше 130 с. Повтор после ошибки бывает только если первая попытка упала быстро и полный ответ ещё успевает до лимита.
- `/ask` принимает только билет от `/parse` (HMAC, `CHECK_TICKET_SECRET`): вызвать DataForSEO в обход Turnstile или с произвольным текстом нельзя.
- В базе хранятся только заявки. Сами проверки нигде не сохраняются: если закрыть вкладку, проверка пропадает (страница предупреждает об этом, пока идут запросы).
- Если сайт не прочитался или на нём нет услуги или города, страница просит ввести недостающие поля. С заполненными полями `/parse` сайт повторно не читает. Так же работает «Try again».
- **Любая страна.** Страна берётся с сайта (Gemini) или из выпадающего списка; список стран и коды локаций — из DataForSEO (`assets/js/ai-check-countries.js`, 192 страны; Россия и Китай там отсутствуют, для них страница предлагает попап «онлайн-бизнес»). В США нужен штат («Austin, TX»), в остальных странах достаточно города. Вопросы: в США — шаблоны из ТЗ; в остальных странах на английском — те же вопросы только с городом (страну задаёт локация DataForSEO, регион в вопрос не пишется); на других языках три вопроса пишет Gemini на языке сайта (при ошибке — английские). Язык сайта передаётся в DataForSEO; если язык не поддержан, повтор идёт с английским.
- **Не местный бизнес** (SaaS, интернет-магазин): ссылка «Not a local business?» под формой и кнопка на экране отказа открывают попап с двумя полями, сайт и email. Заявка попадает в `leads` с `kind = 'online'` и в Telegram с пометкой «онлайн-бизнес»; запросов к ChatGPT и Gemini при этом нет.
- **Страница «спасибо»** `/ai-check/thank-you/` (noindex): после заявки (и обычной, и из попапа) человек попадает на неё. Там дата, «что дальше» и календарь для записи на звонок: адрес страницы записи (Calendly, Cal.com, HubSpot Meetings) берётся из переменной `PUBLIC_BOOKING_URL` (только https); email подставляется в календарь. Пока переменной нет, вместо календаря кнопка «Email us to pick a time». События конверсии (Meta `Lead`, Google, GA4) отправляются с этой страницы один раз на заявку.
- **События для аудиторий** (браузерные, один раз на действие, у каждого свой `event_id`): визит — `PageView` пикселя и тега Google на `/ai-check/` и `/es/ai-check/`; сайт отправлен — `CheckStarted` (Meta, `trackCustom`), `check_started` (GA4), по желанию конверсия Google Ads; результат показан — `ViewContent`, `check_completed`; email оставлен — `Lead`, `generate_lead`, конверсия Google Ads (с thank-you страницы, параметр `kind` = `local` или `online`). Отдельная страница между вводом сайта и результатом не нужна и вредна: проверка живёт в памяти страницы и теряется при переходе.
- **Запуск проверки тоже приходит в Telegram** («▶️ Запущена проверка»): сайт, что определили (бизнес, услуга, место), статус (ждём ответы / просим уточнить данные / сайт не местный / страна не поддерживается) и метки рекламы. Сообщение одно на проверку: повторные вызовы после уточнения полей или «Try again» не дублируются. Так видны и те, кто закрыл вкладку, не дождавшись ответов. В базу это не пишется.
- **Каждая завершённая проверка сохраняется и уходит в Telegram, даже без email.** Страница вызывает `POST /api/ai-check/report`: строка в таблице `checks` (сайт, бизнес, итог, подписанные ответы, метки рекламы), сообщение «Мини-проверка пройдена (email не оставлен)». Принимаются только ответы, подписанные сервером; одна и та же проверка сохраняется один раз. Миграция `db/migrations/004_checks.sql`.
- **Ответы сохраняются с заявкой** (`leads.answers`, массив до 3 объектов): `idx`, `prompt` (точный keyword), `location_code`, `language_code`, `checked_at` (UTC), `answer_text` (полный ответ, markdown), `sources` (все URL: цитаты и ссылки из текста). Каждый ответ подписан сервером (HMAC, `CHECK_TICKET_SECRET`) при получении от DataForSEO, а `/audit` сохраняет только ответы с верной подписью: правки в браузере отбрасываются. `service` и `city` сохраняются так, как были использованы в вопросах. Миграция: `db/migrations/003_leads_answers.sql`.
- **Испанская версия** `/es/ai-check/` и `/es/ai-check/thank-you/`. Тот же код: `assets/js/ai-check.js` читает язык из `<html lang>`, тексты, которые подставляют скрипты (ошибки, статусы, вердикты, даты, страны через `Intl.DisplayNames`), лежат в `assets/js/ai-check-i18n.js` (en/es), статичные тексты — в двух HTML-файлах. Серверные коды ошибок на странице заменяются текстом на её языке. Вопросы к ChatGPT пишутся на языке сайта клиента (Gemini), поэтому испанский сайт получает испанские вопросы и ответы из Испании (`location_code` 2724, `language_code` `es`); примеры на странице — три реальных испанских ответа (Мадрид, Валенсия, Севилья), записанные через DataForSEO. Страница передаёт `ui_lang` вместе с метками: в Telegram приходит строка «Язык страницы», а согласие в `leads.consent_text_version` пишется как `2026-10-14-es` (миграции не нужны). Privacy и Terms остались английскими, на испанской странице рядом стоит пометка «(en inglés)» ⚠️ для испанских посетителей (GDPR/LSSI) юрист должен посмотреть и перевести их. Добавить язык: словарь в i18n.js, две страницы и ссылка-переключатель; тест `tests/i18n.test.js` следит, чтобы ключи, хуки скрипта и структура страниц совпадали.
- Защита: только Turnstile. Лимитов по IP и дневного бюджета в коде нет — следите за расходом в кабинете DataForSEO (там можно поставить лимит) и в Google AI Studio / Google Cloud.

**Распознавание** (`api/_lib/ai-check/match.js`) идёт по правилам ТЗ: домен → точное имя → похожее имя (token set ≥ 0,9 плюс совпадение самого длинного значимого слова, без слов-услуг и города) → имя в тексте ответа. Список бизнесов берётся из блока локальных компаний ответа ChatGPT, а если его нет, из `brand_entities` без каталогов. Шаблоны вопросов и списки исключений лежат в `api/_lib/config.js`.

### Настройка (один раз)

1. **Vercel.** Подключите репозиторий к проекту Vercel и выберите production-ветку. Framework Preset: Other, Build Command и Output Directory пустые. `vercel.json` уже задаёт лимит функций и заголовки noindex.
2. **База.** Neon через Vercel Marketplace: переменная `DATABASE_URL` появится сама. В SQL Editor консоли Neon по очереди (каждый раз очищая окно) выполните `db/migrations/001_leads.sql`, затем `db/migrations/002_leads_kind.sql`. Без второй миграции заявки не сохраняются. Если раньше вы уже выполняли первую версию миграции, сначала выполните `db/drop-old-stage1.sql` (удаляет её восемь таблиц, данных в них ещё нет).
3. **Переменные окружения** из [`.env.example`](.env.example): DataForSEO, `GEMINI_API_KEY`, Turnstile, `CHECK_TICKET_SECRET` (случайная строка), публичные ID Meta Pixel, Google Ads и GA4, по желанию Telegram. После изменения переменных сделайте Redeploy.
4. **Turnstile:** Cloudflare → Turnstile → Add widget → домен `searchwin.ai`, режим Invisible.
5. **Google Ads:** конверсии check_started (сайт отправлен), check_completed (результат показан) и audit_requested (email оставлен; для неё включите Enhanced conversions for leads через тег Google). Метки впишите в `PUBLIC_GADS_LABEL_*`; для аудиторий метка не обязательна.
6. **Meta:** пиксель в Events Manager, его ID в `PUBLIC_META_PIXEL_ID`. Серверный Conversions API и офлайн-конверсии отложены; у событий уже есть `event_id`, чтобы потом добавить их без двойного счёта.
7. **Telegram:** бот через @BotFather, id чата через @userinfobot; бот должен быть добавлен в чат.

Заявки смотрите в Neon (Tables → `leads`) или в Telegram.

### Тесты и локальный запуск

```bash
npm install
npm test          # юнит- и интеграционные тесты (Node test runner, Postgres в памяти через PGlite)
npm run dev       # весь сайт и функции на http://localhost:8787, заявки — на /__dev/leads
```

`npm run dev` работает без ключей: база в памяти; DataForSEO отвечает записанными реальными ответами из `tests/fixtures/dataforseo`; вместо Gemini для демо-доменов (`ironcladtexas.com`, `giannielectrical.net`, `brightline-demo.com`, `dovelewis.org`, `nocity-demo.com`, `saas-demo.com`, `toronto-demo.ca`; для испанской страницы `legalcar.com` (найден на 1 месте) и `madrid-demo.es` (не найден)) отдаются готовые данные, любой другой домен ведёт себя как нечитаемый сайт. Подмена есть только в `scripts/dev-server.mjs` и тестах; в рабочем коде режима заглушек нет. Новые реальные ответы для тестов можно записать с вашими ключами: `node scripts/record-fixture.mjs "best plumber in Austin, TX"`.
